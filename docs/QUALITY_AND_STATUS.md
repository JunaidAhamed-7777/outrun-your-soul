# Quality goals and delivery status

Initial record: 30 October 2026. Documentation exists; implementation, device tests and submission remain pending. Update this file with evidence as work progresses, not optimistic percentages.

## Equal category floors

Slapjam judges Fun, Visual Appeal and Theme Following equally. Treat each as a separate pass requirement. A beautiful screenshot cannot repair unfair combat, and a theme paragraph cannot repair a mechanic unrelated to speed.

| Category | Intended evidence | Failure signal |
|---|---|---|
| Fun | First-time phone player learns dash/return, chooses chain/intercept/flank situationally, completes a run and wants another | Always dash once then return; avoidable-looking unavoidable soul hits; accidental gestures |
| Visual Appeal | Five-second silent clip communicates body/soul speed difference; small-phone image separates path, warning, cuttable bolt and permanent hazard | Decorative clutter obscures endpoints; ribbon looks like a damage beam; muddy lighting |
| Theme Following | Equalizing speeds removes a central route dilemma; speed differences affect attack, defense, timing and reunion | Speed exists only in title, timer or visual effects |
| Repeat-play design | Same room prompts different route/target order across relic families; later session resumes saved progress | Cosmetic upgrades, universal best build, repeated grind or fake daily gating |

These are development tests, not official numerical scoring thresholds or proof of a likely win. Record failures as useful evidence and fix causes before adding breadth.

## Handoff discipline

Each milestone report should state commit, changed behavior, exact tests run, failures, tests not run, and next gate. Keep timing and performance proposals separate from observed data. Do not use concept art as a gameplay screenshot. No claim of finalist-level results, easy winning or multi-day retention is justified before actual play and judging.
